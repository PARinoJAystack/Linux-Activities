# Lab Workflow

## 1. Before starting

Use a Kali Linux VM or other authorized lab environment.

The uploaded task requires that **root is not used for the file operations**. The only explicitly permitted root-level setup operations are the user-management operations (`useradd`/`usermod`) and the later ownership-change step. After switching to `agent007`, keep the workspace operations under that account.

The exact requirement is that all steps except `useradd` and `usermod` are performed using the new user's account, with the ownership change explicitly performed as root. fileciteturn0file0L8-L10

## 2. Create the user

Run the task's specified command as an administrative user:

```bash
sudo useradd -m -s /bin/bash -G sudo agent007
```

Set the password:

```bash
sudo passwd agent007
```

Then switch to the account:

```bash
su - agent007
```

Verify the active account:

```bash
whoami
```

Expected identity: `agent007`.

## 3. Build the workspace

As `agent007`:

```bash
cd /home/agent007
mkdir -p mission/intel mission/ops/backup
cd mission/intel
```

The required structure is:

```text
/home/agent007/mission/
├── intel/
└── ops/
    └── backup/
```

## 4. Create the files

Inside `intel/`:

```bash
touch targets.txt routes.txt keys.txt
```

## 5. Capture the three directory listings

The task explicitly asks for `ls`, `ls -l`, and `ls -la`, with each output redirected to a separate file in `intel/`.

Run:

```bash
ls > listing1.txt
ls -l > listing2.txt
ls -la > listing3.txt
```

Then inspect them:

```bash
cat listing1.txt
cat listing2.txt
cat listing3.txt
```

> Note: Because the listing files are created as part of this step, their appearance in later listings is normal.

## 6. Copy and remove files

Copy `routes.txt` to the backup directory:

```bash
cp routes.txt ../ops/backup/
```

Remove `keys.txt` from `intel/`:

```bash
rm keys.txt
```

## 7. Set permissions on targets.txt

The required permission model is:
- Owner: read + write
- Group: read only
- Others: no permissions

That corresponds to mode `640`.

Run:

```bash
chmod 640 targets.txt
ls -l targets.txt
```

Verify that the permissions are equivalent to:

```text
-rw-r-----
```

The actual owner/group shown may depend on the lab's account configuration.

## 8. Simulate the backup error and recover

Intentionally remove the backup copy:

```bash
rm ../ops/backup/routes.txt
```

Then restore it from `intel/`:

```bash
cp routes.txt ../ops/backup/
```

## 9. Change ownership as root

The task requires the ownership of `intel/targets.txt` to be changed to another user, for example `root`, and then observed as `agent007`. fileciteturn0file0L47-L49

First, while still using `agent007`, note the current state:

```bash
ls -l /home/agent007/mission/intel/targets.txt
```

Switch to an administrative/root context for the ownership change:

```bash
su -
```

Then run:

```bash
chown root:root /home/agent007/mission/intel/targets.txt
```

Return to `agent007`:

```bash
su - agent007
```

Observe the result:

```bash
ls -l /home/agent007/mission/intel/targets.txt
```

The purpose is to observe the changed owner; do not modify permissions beyond what the task requests.

## 10. Capture final evidence

The submission requires a screenshot or text file showing the final recursive listing:

```bash
ls -laR /home/agent007/mission/
```

Save the output to the provided evidence file:

```bash
ls -laR /home/agent007/mission/ > evidence/final-ls-laR.txt
```

If `evidence/` is outside `/home/agent007/mission/`, use its absolute path, for example:

```bash
ls -laR /home/agent007/mission/ > /path/to/this/repository/evidence/final-ls-laR.txt
```

Do not paste invented output into the evidence file. Replace the placeholder only with output generated by your own lab.

## 11. Preserve command history

The submission requires the command history or a copy-paste of commands used. fileciteturn0file0L50-L54

At the end of the lab, capture the relevant history:

```bash
history
```

Copy the commands you actually executed into:

```text
commands/command-history.txt
```

The supplied file contains a clean command sequence as a starting point. Replace or supplement it with your actual executed history.

## 12. Final verification checklist

Before submission, verify:

```bash
whoami
ls -laR /home/agent007/mission/
ls -l /home/agent007/mission/intel/targets.txt
```

Checklist:

- [ ] `agent007` exists with a home directory.
- [ ] `agent007` uses `/bin/bash`.
- [ ] `agent007` is in the `sudo` group.
- [ ] Workspace exists under `/home/agent007/mission/`.
- [ ] `intel/` and `ops/backup/` exist.
- [ ] `targets.txt` exists.
- [ ] `routes.txt` exists in `intel/`.
- [ ] `keys.txt` has been removed.
- [ ] `listing1.txt`, `listing2.txt`, and `listing3.txt` exist.
- [ ] `routes.txt` exists in `ops/backup/` after recovery.
- [ ] `targets.txt` has the requested `640` permissions.
- [ ] Ownership of `targets.txt` was changed as required and observed as `agent007`.
- [ ] Final `ls -laR` evidence has been captured.
